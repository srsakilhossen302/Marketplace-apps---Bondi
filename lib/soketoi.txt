### 1. REST API Endpoints (Base URL: `https://bondi-dev.nasimmondal.dev/`)
All endpoints require a JWT token in the headers: `Authorization: Bearer <TOKEN>`.
 
**Conversations:**
- `GET /conversation` : Fetches a list of all conversations for the logged-in user.
- `GET /conversation/:id` : Fetches details of a specific conversation.
 
**Messages:**
- `GET /message/:conversationId` : Fetches the chat history/messages for a specific conversation.
- `POST /message/send` : Sends a new message. (Payload usually includes `conversationId` and `text`/`media`).
- `POST /message/seen/:conversationId` : Marks all messages in a conversation as seen by the current user.
 
### 2. Socket.IO Configuration (Real-Time Events)
The Socket server runs on the same base URL. 
- **Connection & Auth:** The socket expects the JWT token during connection via the auth payload: `{'token': 'Bearer <TOKEN>'}`.
- **Transports:** Must use `['websocket']` only.
- **Auto-Join:** Upon successful connection, the backend automatically joins the user to their own private room (using their `userId`) and broadcasts a `user_online` / `user_offline` event to others.
 
**Chat Room Socket Events:**
- `join_conversation` (Emit payload: `{ conversationId: string }`): Tells the backend that the user has opened a specific chat screen.
- `leave_conversation` (Emit payload: `{ conversationId: string }`): Tells the backend the user has closed the chat screen.
- `typing_start` (Emit payload: `{ conversationId: string }`): Emits when the user starts typing.
- `typing_stop` (Emit payload: `{ conversationId: string }`): Emits when the user stops typing.
- *(Assume the backend emits incoming messages through a socket event like `new_message` when a user calls the POST send API).*
